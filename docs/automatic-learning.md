# 自动采集、训练与评测更新

普通 `npm start` 默认不开启采集。启用使用：

```sh
npm run start:learning
```

这是一项随游戏服务器运行的本地功能，不依赖聊天窗口或云端定时任务。电脑/服务器停止后不会继续采集。
启动时会在加入页面展示本地对局训练说明。原有战绩保存功能不受影响。

## 默认行为

- 只采集五人、六人且至少包含一次真人手动出牌的完整局；未打完的局、全 AI 局不入库。
- 采集每次实际接受的出牌，含 AI、托管和最后一墩的自动跟牌；非法尝试不会计入。
- 搜索模拟中的克隆牌局没有观察器，不会当作真人牌局写入。
- 每累计 20 局新完整局触发一次训练；成功完成一轮训练/评测后至少间隔 6 小时。
- 每次读取 20 局的新数据，另回放最多 60 局已处理记录，混入自对弈数据。真人对局样本不超过训练样本的 40%。
- 从最近成功训练的候选继续学习，即使它尚未通过上线门槛；训练候选与线上冠军分开保存，避免每批都从头学。
- 单个后台 worker；Python 数值计算限制单线程，worker 尽可能降为较低进程优先级。
- 训练失败延迟 30 分钟重试，连续 3 次错误暂停自动训练，供管理员检查。游戏与采集仍可继续。

只存观测特征、动作特征、匿名座位关系、真人/AI/托管/强制动作来源及终局奖励，不存昵称、玩家 ID、IP、房间码或跨局个人档案。
隐藏牌仅保存在监督标签中，线上决策仍只使用自己的牌和公开信息。
采集压缩文件位于 `.data/learning/rounds/`，不会通过静态网页目录提供下载，也不会提交 Git。
原始记录限制为最近 30 天、最多 1,000 局、总计 512 MiB（先触及的限制生效）。压缩/写入队列繁忙或存储失败时可以丢弃记录，优先保证游戏继续。
未完成局只在内存中暂存，进程重启后丢弃。

## 模型替换门槛

候选先对规则 hard 策略评测，未通过就拒绝，不花时间运行昂贵的旧模型对照。
通过后再比较当前上线模型；尚无已批准学习模型时，对照是原服务器“大师”PIMC，沿用 64 次采样、8 候选及服务器的 `MASTER_PIMC_MS`（默认 1,300 ms）。
PIMC 对照可能花费较长时间，游戏服务器继续使用原策略。

五人、六人分别使用至少 24 个未参与训练的随机牌局，轮换全部座位。
两种玩法都必须在两个对照中满足：平均净升级收益差减去 2.58 倍按牌局聚类的标准误大于零。
这是保守的近似统计门槛，不是每局必胜、真人更强或最优性的保证。
规则异常、数据错误、训练失败、模型格式不符、评测期间旧模型变化，均不能触发替换。

批准后模型以 SHA256 命名并校验，原子更新 `.data/learning/active.json`，保留前一模型引用。
服务器定期读取新版本，并在下一局开始时固定该局的模型；一局中途不会更换。
只有五人/六人“大师”机器人使用通过门槛的模型，其他难度和真人托管保持既有逻辑。

## 本机配置

可在 Git 忽略的 `.run/auto-learning.json` 中设置：

```json
{
  "python": "C:/path/to/python.exe",
  "initModel": "C:/path/to/experimental-model.json",
  "minRounds": 20,
  "cooldownMs": 21600000,
  "evalSeeds": 24
}
```

Python 需要安装 `bench/learning/requirements.txt` 中的 NumPy。
`initModel` 只用于训练初始化，不会因此上线。若不指定则从随机权重开始。
`evalSeeds` 不允许低于 24。改变配置后需重启服务器。

本地状态文件：

- `.data/learning/status.json`：等待局数、冷却、训练/评测中、错误状态及当前模型。
- `.data/learning/state.json`：已处理记录、待完成任务及冷却时间，用于重启恢复。
- `.data/learning/runs/<任务ID>/progress.json`、`worker.log`：阶段与后台日志。
- 同目录的 `result.json`、`evaluation-*.json`：接受/拒绝结果与证据。
- `.data/learning/models/`：通过评测的模型；`active.json` 保存当前与上一个模型哈希。

训练任务会在开始前复制当前批次记录，防止留存清理影响正在训练的数据；任务结束后删除该临时副本。
训练目录中的合成自对弈回放、模型快照和评测报告可供复查；这些任务产物目前需管理员定期清理，不属于原始真人对局留存上限。
异常断电留下且无法自动确认归属的锁会阻止新任务，应检查 `worker.log` 和实际进程后处理，不能直接重复启动多个训练器。

停用：在没有正在玩的对局时停止游戏进程，再用普通 `npm start` 启动。不设置 `LEARNED_AI_MODEL` 时会恢复默认 AI。已产生的后台 worker 可能继续完成当前任务，但普通启动的服务器不会读取自动模型注册表。
如需回滚某个自动批准模型，应先停止自动服务，备份 `active.json`，将其中的 `sha256` 改为已保存的 `previous` 模型哈希，再重启。删除或移动 `active.json` 则退回启动时的默认策略。

## 验证

```sh
npm test
python -m unittest discover -s bench/learning -p 'test_*.py' -v
node bench/learning/automatic-smoke.mjs /path/to/python /path/to/model.json .run/new-auto-smoke
```

端到端 smoke 使用单独目录中的合成真人标记对局，只验证采集→混合训练→评测→拒绝路径。
它故意使用不足 24 的评测种子，必须拒绝上线，不能写入生产 `active.json`，不计入真实玩家数据。
